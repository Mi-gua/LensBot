# DeepLens 优化经验

## 已确立的指导

- **三份独立结论**：交付状态、光学判断、证据强度互不替代。产物导出、loss 下降、`finish` 成功、候选被 promote 为 final artifacts，都不等于验收通过或像质达标。多次出现 finish 成功而合同评估全部 `unknown_tolerance`、`pass_eligible=false`，其同次各 exact 一阶残差可落在 ≤0.5%、≤1.9%、约 2–2.4%、约 4–5.5% 等不同量级；本次三项精确一阶残差为 EFL −1.02%、F/# −1.90%、派生 FOV +0.92%（全部 ≤1.9%），仍无一产生 pass。残差量级本身不是 pass/fail 判据，也不是像质结论；不要把任一次量级当成同类合同的期望值或阈值。
- **验收只在合同口径下进行**：合同写 exact 目标而未给容差时，逐项标 `unknown_tolerance`、`pass_eligible` 保持 false；不得用默认值、历史运行或“接近”推断阈值。只有合同显式写入的项才构成 pass blocker；未写入的指标可作参考，但不产生 pass/fail 结论。无容差的 exact 条目常出现在 `pass_blockers`/`uncertain_requirements` 中而 `violated_requirements` 为空（本次正是如此）——“unknown”不是“违反”，不要表述成失败或达标。
- **逐个一阶目标核对，但先判定定义，再判断它是不是独立自由度**：若合同数值满足 imgh = EFL·tan(FOV/2)，FOV 属“固定像高下的派生结果”，不含独立残差信息。本次合同同样如此：目标 imgh 21.7406 ≈ 50·tan(23.5°) 自洽，实测 imgh 被钉在 21.74，报告 FOV 47.431° = 2·atan(21.74/49.489)，与 EFL −1.02% 符号耦合（EFL 偏小、像高固定则 FOV 偏大）。因此合同评估逐项列的“三个 exact 目标”实际只含两个独立信息（EFL、F/#），FOV 项不应按独立残差解读，也不应据此宣称三个自由度同时失配；派生量偏差不必与源量同量级。半视场与偏差比 g 的既有观察（14.5°≈0.94、20°≈0.97、23.5°≈0.88–0.89、31.5°≈0.74）仍非严格单调，勿过度拟合。若合同以光线追迹或其他方式定义 FOV，则它独立，必须单独核对。
- **一阶漂移要分层归因**：同一偏差在多次续跑中稳定不变并写入导出产物 → 目标函数覆盖/参数化层面的残留，换种子或加迭代都改不动，杠杆是显式覆盖该一阶项、明确验收容差或改变结构。本次同一会话内四块链式细化给出直接例证：EFL 随块单调漂移（−0.37% → −0.85% → −1.02%），同期像质改善，说明继续同管线精化只会把该受保护一阶项推得更远。但残差的量级与符号跨任务并不固定（已见 −EFL/+F#/+FOV、+EFL/−F#/−FOV、−EFL/−F#/+FOV 等组合）；只有同一任务内多个独立会话给出同向残差才算有意义的族间信号。也要看残留出现在哪个阶段及读数量纲：`deeplens_inspect_checkpoint` 的中间漂移读数与最终导出残差口径/单位可能不同，不可直接换算或比较；“细化阶段必然引入一阶残留”也不成立。
- **降低 LR 是稳定器，不是恢复器**：`deeplens_adjust_strategy(action=reduce_lr)`（applied=true、lr_scale=0.5、rollback_count=0）是**会话级**设置，同一 session 后续 finetune 的执行元数据回显 `strategy_lr_scale=0.5`，未调用时回显 1，新会话恢复 1。可复用顺序：先在聚合 loss 与像质之外确认受保护一阶在块间漂移 → 若预算尚余则降 LR 再看一块的增量 → 若偏移已稳定成型且无更多可比块，杠杆在显式覆盖该一阶项、明确容差或改结构。本次实例：在会话前三块（lr_scale=1）之后、仍余一个等预算块时调用降 LR，随后那块（lr_scale=0.5）导出并被选为最终候选，verdict 称它把受保护 F/# 的出血从 −3.19% 收敛到 −1.90%；但同块 EFL 仍继续漂移——降 LR 改变的是受保护一阶项之间的取舍方向，不是整体恢复成原始目标。归因仅来自 verdict 文字，且单块、同会话无 lr_scale=1 对照，不能确立因果。此前另有一例在细化末期调用、未能回收已成型偏移；一例降 LR 后残差收紧但迭代仍在继续。比较块时必须记录当块 lr_scale，且不要跨会话沿用旧尺度。
- **bfl/thickness 是 starting geometry**：末态 BFL 相对初始值常见变化约 1–6%，本次 18 → 16.88 mm（约 −6.2%）、TTL 75 → 75.01 mm（约 +0.01%）；该带宽随任务浮动，不构成阈值，合同未把它写成硬约束时不构成违规，packaging 仍可判满足。参考处方后焦距常与合同起点相差很大（多份参考的后间距约 35.5–85 mm，而合同起点为 12–18 mm），此时必须重导后组光焦度而不是缩放参考处方；整体统一缩放不能同时满足 EFL 与 BFL 时同样如此。
- **评价覆盖范围是证据强度的一部分**：必须逐次运行确认，不能沿用上一次判断。ray-sampling 可达视场可能窄于合同目标视场，此时边缘场结论受限；细化过程中采样视场收窄不是改善信号。本次边缘场有效光线比例仍为 null（边缘 RMS spot 35.7 µm、边缘 MTF50 切/弧矢 19.34/11.81 cy/mm、中心 RMS spot ≈20 µm），边缘结论的有效性不可默认，应记为覆盖缺口；“畸变光线全部有效”属另一套口径，不能替代 spot/MTF 的有效光线比例。
- **指标合理性要自检**：与几何/传感器映射自相矛盾的读数应标为低置信并复核口径，不得直接当作已验证缺陷；后续自洽的读数也不能反过来追认此前异常读数为真实缺陷。跨场/跨方向排序前须先确认定义与采样：边缘 MTF50 高于同次中心 MTF50 已多次出现（本次边缘 19.34/11.81 vs 中心约 11.7 cy/mm），切/弧矢各向异性比已见约 1.15–2.3，本次约 1.64，说明该比值可低于 1.2，不要把 1.2 当硬下界。边缘 MTF50 与边缘 RMS spot 量级互相呼应可提升读数可信度，但口径不一致时不能因“看起来合理”就升格为已验证像质。绝对几何 MTF 数值不能与衍射 MTF 或厂商数据直接比较。
- **只有实际应用并进入优化与可比评价的候选才产生证据**：被检查但未采纳的起点/探针不提供支持或否定。本次三个种子里只有 seed_198（applied=true）进入优化并被选中，另两个 applied=false 的种子（Tessar、Cooke triplet）只被检查，不能据此对这两个族作支持或否定。族数、独立起点数必须按 session_id 与 artifact 核对，不能只信 verdict，也不能只信可能被截断的 trace。种子卡 `applied` 标志与最终选中的族既出现过一致（本次），也出现过相反，该标志不能单独作为证据。
- **比较时必须固定协议**：处方口径、共轭、光谱与权重、视场/孔径定义、调焦、采样（含 ring/arm/spp/test_per_iter 等块级设置）、有效光线处理与指标类型。几何单波长 MTF 与衍射 MTF、厂商数据不可直接比较，只能在同一协议内做相对判断。“distinct candidates” 不等于独立结构族：同一 session 内顺序 finetune 是同一 lineage 的连续细化（本次 candidate-001→004 即此类，四块链式、每块 source_lens 为上一导出候选），跨 session（不同 session_id、各自新 curriculum）才是不同起点。族系仍须按 artifact 核对。
- **收敛与选型要区分三类信号**：(a) 像质平台化，(b) 一阶目标失控或固定偏移，(c) 不同独立结构族收敛到相近的残余上限。等预算分块中末期块的小幅 loss/像质下降可能掩盖一阶回退，属交换而非全面改进。停止判断要按块、按指标分辨率看增量，不能只看聚合 loss；也不能假定最新导出的候选就是合同下的最优候选。本次选型为“无支配候选”：同一 lineage 内 candidate-002 头部 EFL 更紧（−0.37%）但 F/# 残差更大（−2.51%）且像质更差，candidate-004 整体更均衡但 EFL 更松，两者互不支配；只能在“都偏离”的候选间按整体协议比较，这不改变“无容差即 unknown”的验收口径。本次停止模式：无可支配候选 + 无剩余可改变决策的实验（降 LR 假设已用一块测试过）→ 停止。注意 verdict 的模式措辞可能是“一个受保护一阶量继续漂移而其他量收紧”，与此前“所有 exact 残差同向”不同；不要硬套单一模式模板，须逐指标看方向。
- **细化预算与分块**：把 fine-tune 拆成等采样设置的多个块（保持块级 test_per_iter/ring/arm/spp 一致）既便于逐块判断平台化，也让总预算可超过 intake 建议值而不失可比性。本次为 curriculum 2000 + 4×2500（块级 test_per_iter=100 / ring=32 / arm=8 / spp=512），fine-tune 总量 10000 步，约 intake 建议 5000 的 2 倍。块间 source_lens 为上一导出候选、optimizer_reinitialized=true 属重新初始化，不是同一轨迹的简单延长。块的可比性还要记录当块 lr_scale（本次前三块 =1、第四块 =0.5），并记住该值只在本会话有效。

## 待验证假设

- **一阶残留更可能来自覆盖面/参数化而非种子或拓扑**：证据来自三个任务——一个任务三个独立起点复现约 4–5.5% 同向残差；另一任务两个家族复现约 2–2.4% 残余模式；本次单个起点（未做多种子对照）在四块细化下呈单调 EFL 漂移。量级与符号跨任务不同，且多为 verdict 摘要而非逐族 artifact 数值，仍需独立复现，不能上升为定律。
- **两个独立结构族在同一评价协议下收敛到相近残余上限**：已出现三次——边缘多色 spot（约 148–155 µm）出现在两个全 spherical 族之间；约 5% 一阶残差出现在三个起点之间；约 2–2.4% 一阶残差出现在两个家族之间（均为 verdict 口径）。复现时务必先用 artifact 确认候选确属不同族，并固定指标口径。本次只应用了一个族，不构成新证据。
- **最小充分结构的适用边界**：4 片 Tessar 型曾在一次中等难度任务中被选为最终候选；精简后的内光阑 Double Gauss 已两次被选为最终候选（一次约 6 元件/11 面、全 spherical）。两个方向都有，不能据片数断言族优劣或“最少片数”。要检验须把简化对照真正送入优化与同一比较协议。
- **对称/内光阑 Double Gauss 类起点**：在多类中口径、中速任务中给出物理可行、一阶接近的候选，且已两次被选为最终候选（按放慢到 F/4.0 把参考约 12 面减为约 10 个折射面，全 spherical）。仍属逐任务观察，不能称为“优选族”。
- **降低 LR 的调用时机**：本次在会话仍余一个等预算块时调用降 LR，随后那块被选为最终候选且 F/# 出血收敛；此前一例在细化末期调用、未能回收已成型偏移。可能“仍有可比预算时降 LR”比“到最后再降”更有信息量，但每会话各只有 0–1 个 0.5 尺度块，无同会话同预算对照，仅作假设。
- **非球面这一自由度在当前工作流里无法由优化工具引入**：没有可添加非球面的工具，供应的起点也全为全球面（本次三个候选 asphere_count 均为 0）。对照只能在 seeding 阶段提供带非球面的种子、并在同一结构族内留全 spherical 对照才可能实现；此前单面非球面探针只被检查、或在与族混杂的条件下失败/保留，均不能推出必要性结论。停止理由中的“该实验不可得”属工具能力限制，不是光学证据。
- **续跑收益是双面的**：续跑通常保住中心像质，但受保护的一阶项基本不动，末期块还可能牺牲一阶项换像质（本次 EFL 随块单调变差，边缘 spot 由约 55 µm 改善到约 36 µm）。链式 finetune（optimizer_reinitialized=true）既观察到后代被选为最终候选（本次），也观察到后代被其父候选淘汰，还观察到一阶与像质同时收紧。既不能据该标志断定退化，也不能断定进步，应按实测逐块增量判断；续跑前先明确“什么证据会改变决策”，并以等预算分块跟踪每块下降量与覆盖范围。
- **派生型一阶量是否应计入残差考核口径**（FOV 由 EFL 与像高决定时，是否只考核 EFL 与像高）：本次及此前合同都把派生 FOV 当独立 exact 条目并列入 `pass_blockers`。属口径设计问题，逐案确认，不要默认套用。

## Backend/tool notes

- `deeplens_curriculum` 与 `deeplens_analysis` 的状态标志不一致是可复现的软件模式：本次 curriculum 会话（session_id=20053acb37）返回 curriculum_json=not_ready / has_curriculum_json=false；随后 analysis 报 has_curriculum_json=true 并给出 attempt 级 curriculum.json 路径，该路径被成功用作 finetune 的 source_lens；也再次出现“curriculum 后不插 analysis 直接 finetune 仍成功”（source_lens 指向 attempt-001-curriculum/curriculum.json）。显式再分析是安全的确认步骤而非必需前置；artifact 可用性以实际读取或路径被下游成功消费为准，布尔标志本身不能单独作为缺失证据。
- `deeplens_analysis` 返回的 `candidate_json` 可能与你传入的 `lens_json` 不对应（曾见分析结果指向另一会话已导出的候选）；但传 candidate 路径时 `analysis_json` 也可能就等于该 `lens.json` 路径（本次四次 stage=candidate 均如此）。归因前先按 artifact 确认身份，不要假定分析结果一定描述你问的那个候选。
- `deeplens_adjust_strategy` 是少数能直接影响后续优化行为的可见工具：调用后同 session 的 finetune 执行元数据回显 strategy_lr_scale=0.5（本次调用返回 applied=true、lr_scale=0.5、rollback_count=0，随后第四块回显 0.5），未调用时回显 1（本次前三块），新会话恢复为 1。它只改变可见的 LR 尺度，不产生任何光学结论；使用后必须重新分析候选，并按块、按会话记录 lr_scale，以免把不同策略下的结果当成同一轨迹比较。
- 调用 `deeplens_finetune` 时逐项确认 `iterations_executed` 为正、`source_lens` 是预期起点、`optimizer_reinitialized` 与 `strategy_lr_scale` 取值（本次各块 requested=executed=2500，源与标志均符合预期）。历史教训仍有效：零步训练却重新导出候选的记录不能用于证明结构平台化。
- `deeplens_inspect_checkpoint` 提供逐个一阶目标（efl/fnum/fov）的漂移，适合在聚合 loss 或像质指标之外单独做一阶受控性检查。但导出点漂移小不代表细化之后仍小，且其读数口径/单位可能未在 trace 中说明，不能与最终导出残差直接换算或比较。它并非每次运行都会调用（本次未调用）；未调用时不要凭空推断 checkpoint 级漂移。
- `deeplens_compare_candidates` 只用一套协议比较多个候选，不会自动选出赢家；本会话甚至未调用它，选型结论来自逐候选 analysis（并参考了比较协议文档）。重复调用同一比较不产生新的独立证据，返回的 distinct candidates 计数不等于独立结构族。被比较的候选仍需各自在最终口径下重新分析，选型结论通常来自这些分析而不是比较工具本身。
- 结构描述以 artifact/分析结果为准，不要依赖叙述性摘要或元数据字段：候选摘要中的族名、组数、元件数/面数，种子卡上的 `applied` 标志，乃至最终 metrics 块记录的 candidate_id，历史上都出现过与判词所称不一致的情况，也存在一致的情形（本次 `applied` 与 candidate_id 均与 verdict 相符，但 verdict 所述“11 面”与种子卡表面计数口径存在出入）。逐次核对，不预设一致或矛盾。种子卡对合同本身的解读也可能与 typed contract 不符，合同自由度口径以 typed contract 为准。
- 分析报告中的可制造性/几何信号（如 min surface vertex spacing、packaging_constraints_satisfied）可用来排除自交或明显不可实现的候选（本次最小顶点间距 3.14 mm、packaging 约束通过），属几何可行性证据，不替代合同验收。
- `finish` 失败有两类，处理路径不同：
  - 状态/artifact 相关：ok=false 而 error 字段为空，此时先复核实际 artifact 并显式传入候选 `lens_json` 重新执行 `deeplens_analysis`，再决定重试路径。
  - 判词证据解析相关：ok=false、error 为空，observation 内给出 code=`invalid_verdict_evidence`、recoverable=true 及 unresolved 条目列表。已见两种形态：把数值与说明文字一并写进条目（如 `deeplens_efl_mm=28.7016 (+2.51% vs target 28)`）；以及引用当前状态不可解析的键（如 `packaging_constraints_satisfied`、`pass_eligible`——它们在合同评估块里存在但不是可解析的 metric key）。verdict evidence 应给可解析的指标键，说明文字另行书写。本次 `finish` 返回 ok=true 并把候选 promote 为 final artifacts，未出现该类解析错误；但 `has_final_json`/`has_final_zmx`=true 只说明产物存在，不是验收（本次合同评估仍为全部 unknown_tolerance、pass_eligible=false）。
- 工具失败（即使错误字段为空，或形如 `tool_execution_end` 的 ok=false）不是光学证据；同一 analysis 内部错误的重复出现是软件故障谱系，不是多个独立光学实验。先修复或更换可信评价路径，再形成光学经验。
